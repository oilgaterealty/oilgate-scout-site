# Akron bounded map data

## Building archive

`akron-buildings.pmtiles` is a derived database built from the Overture Maps
Buildings theme release `2026-08-19.0`. It is clipped to Scout's existing,
confirmed Akron operating polygon; it is not an Akron municipal boundary and
does not expand Scout's configured geography.

Source GeoParquet:

`https://overturemaps-us-west-2.s3.us-west-2.amazonaws.com/release/2026-08-19.0/theme=buildings/type=building/part-00057-feed1627-f8ad-5387-b1bd-28abea82ce33-c000.zstd.parquet`

The archive contains 172,951 spatially conflated footprints at zoom 14. Overture
prioritizes OpenStreetMap geometry and fills non-overlapping gaps with compatible
sources including Microsoft ML Buildings; Scout does not stack a separate raw
Microsoft layer. Heights use Overture height estimates first, then floor count,
then a conservative footprint/type-aware fallback. Feature IDs are assigned by
the pinned source-ID ordering instead of a truncated hash: all 172,951 IDs are
unique, deterministic, and safe to expose as JavaScript numbers. The generator
fails closed if source IDs or packaged feature IDs are not unique.

Build command (requires DuckDB's spatial extension and the official
`go-pmtiles` CLI):

```text
python scripts/build-akron-buildings.py --pmtiles <path-to-pmtiles> --output public/data/akron-buildings.pmtiles
```

Archive facts:

- size: `4,207,590` bytes
- SHA-256: `69c184efdcf759ec30b879a3666fc03b8d1fb9131820d7c9276db8523f015a83`
- PMTiles v3; MVT; gzip; zoom 14 only (overzoomed for closer views)
- 196 addressed tiles, 180 directory entries, 163 unique tile contents
- bounds: `[-81.672, 40.965, -81.369, 41.191]`

The browser source uses `/api/map/akron-buildings`, not the direct public-file
URL. That same-origin endpoint supplies `Accept-Ranges`, `Content-Range`, ETag,
and immutable caching so PMTiles reads only the header/directory and visible
tile ranges. On first detail access, the server/worker lazily reads and
checks the size and SHA-256 of this bounded archive, then caches its bytes in
process memory; the full archive is never added to the browser's cold-start
payload.

## World-surface, tree, and canopy packages

Three further bounded packages give the map a ground surface and a real canopy.
All are regenerated by scripts in `scripts/`, all are clipped to the same Akron
envelope, and none of them expand Scout's configured geography.

| File | Contents | Source | Build |
| --- | --- | --- | --- |
| `akron-landcover.geojson` | 2,600 ground polygons in 14 classes (wood, forest, scrub, park, golf, cemetery, orchard, grass, wetland, farmland, water, residential, commercial, industrial, civic) | OpenStreetMap via Overpass | `python scripts/build-akron-world.py` |
| `akron-trees.json` | 26,594 surveyed OpenStreetMap trees (`natural=tree` nodes plus `natural=tree_row` densified at 11 m), stored as 1e-5-degree integers | OpenStreetMap via Overpass | `python scripts/build-akron-world.py` |
| `akron-canopy.json` | Measured percent tree-canopy cover on a ~90 m grid (282x279 cells) | NLCD Tree Canopy Cover 2021 (USFS/MRLC) via the public MRLC GeoServer | `python scripts/build-akron-canopy.py` |

`akron-terrain/` holds 260 Terrarium DEM tiles at z13 and z14, built by
`python scripts/build-akron-terrain.py`.

Why a canopy raster as well as OSM: OpenStreetMap records woods, parks, and
surveyed street trees, but not the ordinary yard canopy that covers most of
Akron's residential neighbourhoods. Drawing only OSM vegetation left genuinely
tree-lined streets looking bare. The canopy grid answers "how much canopy
actually stands over this ground?" from published measurement. The map renders
canopy cover; outside OpenStreetMap's surveyed `natural=tree` nodes it does not
claim to locate individual trees.
